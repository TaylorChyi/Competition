# 参赛包发布流程

每次代码修改交付时，维护者负责完成以下步骤。接收者只需要从 [Latest Release](https://github.com/TaylorChyi/Competition/releases/latest) 下载 `CoreGeek.tar.gz`。

## 1. 打包并检查

```bash
python3 tools/package_bot.py
python3 -m unittest discover -s tests -p test_package.py -v
```

产物是 `dist/CoreGeek.tar.gz`。检查直接打开它，验证包与当前源码一致、独立解压、直接 Python/Bash 两种入口和默认/试验策略的 HTTP 指令。不要在检查过程中换成另一个包。

## 2. 推送源码，发布对应提交

提交、推送源码与文档，取完整提交 SHA。用 `bot-日期-短SHA` 作为 Release 标签；发布说明用临时 Markdown 文件准备，包含本次变化、源码 SHA、包 SHA-256、启动方法和验证范围。

```bash
gh release create <标签> dist/CoreGeek.tar.gz \
  --repo TaylorChyi/Competition \
  --target <完整提交SHA> \
  --title 'CoreGeek 最新参赛包' \
  --notes-file <发布说明文件> \
  --latest
```

这条命令由维护者执行；尖括号是需要填写的参数，不是接收方启动命令。源码推送成功只表示代码已保存，Release 和附件上传成功才算交付。

## 3. 从 GitHub 下载验证

```bash
gh release download <标签> --repo TaylorChyi/Competition \
  --pattern CoreGeek.tar.gz --dir <新的临时目录>
```

下载到新的临时目录，比较文件 SHA-256 与本地待发布包。也可将下载的绝对路径传给检查：

```bash
COMPETITION_PACKAGE_PATH=<下载包的绝对路径> \
  python3 -m unittest discover -s tests -p test_package.py -v
```

确认该 Release 标记为 Latest，附件是 `CoreGeek.tar.gz`，源码 SHA 正确，下载哈希一致，才对用户报告发布成功。

## 4. 保留最新版本

新版本通过下载检查后，删除此前 `bot-` 标签对应的旧比赛包 Release 及其资产。当前用户要求只保留最新包；不要在新包可用前删除最后一个有效版本，也不要清理其他用途的 Release。源码 Git 历史用于追溯，无需重写。

首页始终使用固定地址：`https://github.com/TaylorChyi/Competition/releases/latest/download/CoreGeek.tar.gz`。私有仓库的下载者需已有访问权限。

## 外部事实证据

- 检查时间：2026-09-18，Asia/Shanghai。
- 触发原因：改为 GitHub Releases 交付，需要核对附件上传、提交绑定和 Latest 下载入口。
- 本地版本事实：GitHub CLI 2.92.0；已读取 `gh release create/download/delete --help`，当前仓库发布前没有 Release。
- 查询入口与来源：[GitHub 官方 Latest 链接说明](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)、[GitHub CLI create 手册](https://cli.github.com/manual/gh_release_create)。网页未提供固定发布日期。
- 采用结论：使用 `--target` 绑定提交、随 Release 上传资产、`--latest` 标记当前版本，通过 `/releases/latest/download/CoreGeek.tar.gz` 提供固定下载地址。
- 残留风险：私有权限和发布成功状态以实际 API、重新下载及哈希校验为准；本地打包检查不等于官方运行环境验收。
