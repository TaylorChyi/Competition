## 平台可以修改启动命令

复制下面的一整行作为启动命令，末尾端口仍按平台要求填写。命令先运行 Python 的内联预检代码，因此不依赖固定路径下已存在 `main3.py`。

<!-- START_COMMAND -->
```bash
python3 -u -c 'import hashlib,os,sys; from pathlib import Path; print("Caffeine-Taylor",flush=True); r=Path("/home/docker"); expected="10b485a367aac2d2f0cee56cc3bb9343f153de07e180ca487061f3d0bd965edc"; print("CoreGeek preflight | cwd="+os.getcwd(),flush=True); print("CoreGeek preflight | directory="+str(sorted(p.name for p in r.iterdir()) if r.is_dir() else "MISSING"),flush=True); entries=sorted({p.resolve() for pattern in ("main3.py","*/main3.py","*/*/main3.py","*/*/*/main3.py") for p in r.glob(pattern) if p.is_file()}); print("CoreGeek preflight | entries="+str([str(p) for p in entries]),flush=True); matches=[p for p in entries if (p.parent/"MANIFEST.json").is_file() and hashlib.sha256((p.parent/"MANIFEST.json").read_bytes()).hexdigest()==expected]; print("CoreGeek preflight | expected="+expected[:12]+" matches="+str(len(matches)),flush=True); len(matches)==1 or sys.exit("CoreGeek preflight FAILED: need one matching extracted package; check upload/extraction logs and listed paths"); (matches[0].parent/"src/agent/server.py").is_file() or sys.exit("CoreGeek preflight FAILED: package runtime is incomplete"); os.execv(sys.executable,[sys.executable,"-u",str(matches[0]),*sys.argv[1:]])' 6666
```
<!-- END_COMMAND -->

它先输出 `Caffeine-Taylor`，再输出工作目录、`/home/docker` 的第一层内容、有限层级内的入口候选和当前版本匹配数。随后按本版 `MANIFEST.json` 的完整 SHA-256 定位唯一入口，直接用已有 Python 启动，HTTP 服务保持前台运行。命令支持 Shell 或正确处理引号的命令参数解析器。

| 预检结果 | 含义与下一步 |
| --- | --- |
| `directory=MISSING` | 该容器中连 `/home/docker` 都不存在，需查平台实际挂载位置。 |
| 第一层只有压缩包，`entries=[]` | 当前检查范围内没有解压后的入口，需查看平台解压日志；命令不擅自解压未知文件。 |
| 候选含 `CoreGeek/CoreGeek/main3.py`、`matches=1` | 文件被额外套目录，预检会直接定位并启动。 |
| `matches=0` | 检查范围内没有与本版清单匹配的入口；需核对实际解压路径、清单是否完整及预检命令是否来自同一 Release。不能仅据此认定用户上传旧包。 |
| `matches=2` 或更多 | 同版本有多个解压目录；打印路径并停止，避免任意选一个。 |
| `runtime is incomplete` | 入口和清单存在，但 `src/agent/server.py` 缺失。 |
| `CoreGeek startup` 后出现 `listening on ...` | 程序已经启动；再看平台请求与回合日志确认对局连通。 |

搜索根固定为 `/home/docker`，只检查入口位于其根部或下方三层目录的情况。若平台解压到其他位置，需依据日志调整搜索根；不能从当前报错推断真实位置。

## 平台启动命令固定

上传 Release 的 `CoreGeek.tar.gz` 后，平台需要把包内入口放到它固定执行的 `/home/docker/CoreGeek/main3.py`。例如从 `/home/docker` 解压单根目录包会得到这一位置；若先创建 `CoreGeek` 再完整解压，会多出一层目录。

如果结构修订版仍然报同样的错，需要平台提供两项信息即可继续定位：

1. 本次上传文件的解压命令及成功/失败日志。
2. 启动前容器里 `/home/docker` 的目录列表，以及实际 `main3.py` 所在路径。

找不到入口发生在包内程序运行之前；修改算法、捕获 HTTP 异常或再加包内日志都无法观察这一阶段。
