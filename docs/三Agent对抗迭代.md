# 三 Agent 对抗迭代

更新：2026-09-18。三个 GPT-6 Astra Agent 从已发布的 `b471f443a9ac2ab893b1a15102818ace57a6dcd6` 独立修改、互相审查并参加同一裁判下的循环赛。每个 Agent 连续复用三轮，未用不同身份重复创建，也未训练神经网络。

## 策略与互相反制

- **Alpha：经济与延迟回血。** 发现固定血线等到基地危急才运券会来不及，拆分返程和使用；后续减少健康基地预购占款，并按下一张基地券的实际价格留钱。
- **Beta：火力、操作者与采购。** 多种火箭/加特林组合在强压力场景退化，保留三电磁炮；采纳 Alpha 的延迟回血思路，改为按附近来袭伤害预估使用时机，机会购药同时预留基地升级款。
- **Gamma：合法召唤攻击。** 首轮大量购大型令反而拖累自己；二轮用小型/中型令确实增加对手波次，但仍输掉多数换边局。第三轮只考虑满级且重伤敌基地的终结机会，避免常规召唤给对手送击杀积分。
- 三方相互指出库存满时购买失败、把未卖矿的估价当现金、基地券返程过晚、采购资金被药剂或召唤占用等弱点。开发失败与消融记录保留在各自 `NOTES.md` 和 JSON 中，不能用少量开发胜局替代正式循环赛。

## 固定裁判与计分

- 从75金币、零炮台起步，每半场10天/1300回合，保留损伤、真实采矿交易、购买支出、死亡与复活。原有两种重波次、出生范围和难度保持；没有为了胜率减少怪物数量。
- 每一组对抗由相同种子、相同波次的两半场组成，交换双方出生位。先按基地摧毁先后判半场结果；都活到结束或同时死亡时比较积分。一胜一负时按两半场总分，平局单列，绝不计为胜利。单胜加单平判胜属于对任务书未明确组合的本地解释。
- 本地积分只包括击杀分与完整存活日分，后者为每一天 `10 × day`；没有任务样本，所有候选任务积分均为0，不能据此宣布完整官方评分已经复刻。
- 独立核对任务书后修正共享尾矿（不足时每个工人仍各得一份）、夜间采矿、腾空格移动链；补齐召唤令、每日上限、炸弹、眩晕、墙修复与墙升级。每个角色一回合不能既执行自身动作又操作炮台。
- Beta指出移动链问题后，首轮24半场重新执行。修正前原始诊断仍保留，未混入正式选优。正式三轮使用相同最终裁判；后续仅扩展执行脚本的阶段入口与发布判定。
- 每半场为双方重新加载隔离模块，固定裁判和候选源码指纹；候选比赛期间变化会中止，未使用模拟器内部状态或未来波次作为 Bot 输入。

## 范围与仍未知的机制

机器人目标优先级、寻路、出生位置和后续波次仍是两种本地假设。`heavy-advance` 是机器人持续逼近基地且可能隔墙伤害基地的压力模型；未得到官方引擎验证。任务、宝藏、新闻价格变化和直接玩家建筑伤害没有完整模拟。两队同回合对同一机器人造成相同伤害时，本地归属仍按既有固定顺序，正式归属未知；换边减少阵营偏置，但不能消除这个模型差异。

循环赛与保留种子上的胜率只针对所列候选和模型。即便出现全胜，也无法推出对未知对手、地图或正式裁判100%胜率。具体失败必须保留，不能把平局算赢、挑选有利对手或降低波次。

## 复现

```bash
python3 tools/run_league.py --stage round1
python3 tools/run_league.py --stage round2
python3 tools/run_league.py --stage round3
```

首两轮使用各 Agent 的 `round1/`、`round2/` 快照，第三轮使用最终冻结目录；旧报告保留当次路径与哈希。当前 `lab/arena.py` 已按实战反馈修订，旧实验精确复现需先在独立工作副本中用 `lab/league/judge_snapshot.py` 替换 `lab/arena.py`；源码指纹可与报告核对。复现会覆盖对应阶段结果，请先复制需要留存的报告。旧 holdout 没有执行，也不用于发布。实验脚本供维护者使用，接收者直接下载最新Release参赛包即可。
