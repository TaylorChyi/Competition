2026-09-18。依据用户提供的 teamB 实战复盘，对已发布 `b471f44` 版检查。当前拿到的是逐回合摘要，没有这场比赛完整的输入、响应与结算文件，因此以下场景是回归与压力测试，不能称为原局重放。

## 哪些判断成立，哪些还不能下结论

| 反馈 | 代码、规则核查与处理 |

| 工人长时间在同一点collect说明效率低 | 矿石采空会随机刷新；没有每回合矿点、库存和执行结果，不能只看重复动作判低效。当前补回程预算与临近日落采购限制，避免消耗操作时间却无法在入夜前交付。 |
| 围墙没挡住对基地的攻击 | 官方没有明确保证围墙挡弹、最近建筑吸引火力。墙按可被攻击的建筑处理，操作者风险计算不再依赖墙替其承伤；压力测试保留直接推进基地的情形。 |
| 基地毁后1000回合空转 | 角色全灭时没有合法可执行动作，返回空指令合理。不能把空转本身当成新的决策错误；修复重点在基地毁之前。模拟器也补上基地毁后停止团队操作，避免继续赚分。 |

按任务书70白天+60夜晚，第二天白天为131–200，第二晚为201–260。用户摘要中的“第二天白天131–260左右”不能作为阶段判定依据。基地占2×2，接口坐标是左上角；本版没有改成3×3。

## 本版可检查的行为

- 持有可用基地券且已到合法位置，立即发出使用指令；通过下回合的基地等级、HP和动作结果确认是否实际生效。
- 采购前同时检查现金、背包和去商店再回防的完整路程；夜间不再启程购物。药品采购保留下一张基地券100/150金币，濒死角色急救有明确例外。
- 日落前按路线回防并调整到炮台后侧；左右阵营有镜像回归。小幅假设风险变化不反复占用开火动作，高死亡风险才移动；濒死时允许离开操作范围，随后不会直接走回致死位置。
- 使用道具的角色先从炮手分配中排除，其他可用角色重新分配；来袭机器人的潜在攻击对操作者构成威胁时，提高其清理优先级。
- 只主动选择 `targetTeam` 指向我方的机器人。高血目标允许多炮合法集火，同回合用预留伤害避免明显过量。
- 日志首行仍为 `Caffeine-Taylor`。每回合追加 `battlefield`：基地等级和位置、角色位置/HP/背包计数、各炮台范围/冷却/附近操作者/最近来袭距离及未开火状态。`attack-issued` 只代表发出攻击，真实结果以随后请求为准。

## 裁判修订与实验边界

旧三Agent循环赛的裁判与结果留在[历史报告](三Agent对抗迭代.md)，没有把失败删除或改为胜利。收到实战反馈后，三位Agent继续交叉审查，合并经济和防守修复；对手包括已发布版，以及旧第二轮领先的Beta。

本轮配置固定于[experiment.json](../lab/field/experiment.json)：

- 第一、二晚每队35、36只来自用户摘要；种类比例、第三晚以后的增长仍是假设。
- 用所报三座炮台、四块墙的坐标反推防守方基地(30,10)，再镜像另一边；其余矿点与地形沿用样例。这是重建压力场景，未取得实际整张地图。
- 分别测试就近攻击、优先攻击操作员、持续推进基地三种目标选择。三个模型代表未知机制的不同可能，不能说官方采用其中某一个。三者目前都假设机器人一回合移动或攻击二选一；官方没有明示这一点，同轮移动后攻击的风险仍未覆盖。
- 修复死亡日记录，防止当日上午刚死的角色当天复活；阵亡角色次日第20回合后才复活，保留背包。建筑升级距离在模拟中按整建筑邻接解释，Bot仍选坐标锚点一格的保守合法子集。
- 从75金币、零炮台起跑，连续十晚，双方换边。每个半场单独计算胜负，分胜时以总积分决出配对结果；任务积分未建模，双方均记0。
- 首次集成开发种子22001、22002；原计划独立实验当时未执行；第2轮结束前另以23011就近、23012操作员、23013推进各一组做独立发布对照，配置与原独立计划不同，结果单列。开发阶段发现回退后保留失败，继续修复；随后用户明确更新为每对10组、并列加赛5组、每轮冠军发布的锦标赛，发布选择按新的[赛制](锦标赛进度.md)执行。没有查看独立种子后重新挑参数。

## 验证和复现

```bash
python3 -m unittest discover -s tests -p 'test_field*.py' -v
python3 tools/run_tournament.py --round 1
```

锦标赛读取被冻结的候选，不把裁判内部状态或未来波次传给Bot。旧 `run_field_check.py` 是首次集成开发的实验入口，未经独立复核；重跑旧实验前需恢复对应快照并另存证据。运行包不包含实验环境、对手或开发数据。

最新发布采用第3轮锦标赛冠军Gamma，在共同修复上采用两座前炮、一座侧后炮布局；本轮12胜0平8负，40/40半场过第二晚，21/40撑完十晚。112项回归检查通过，包含升级券、资金与路线、操作员与火控、诊断日志、模拟裁判和真实HTTP归档检查。Linux amd64 / Python 3.11.16的3个独立容器共14次启动、56次HTTP请求通过；启动首行保持`Caffeine-Taylor`。包内9个运行模块逐字节对应冻结冠军，正式比赛仍需复测。

先前以第1轮Alpha冠军独立对照实战旧版本`b471f44`的3组换边中，Alpha 3/3组胜；第二晚6/6半场存活，旧版5/6。新旧双方仍有十晚前失败，详见[锦标赛进度](锦标赛进度.md)，不承诺正式胜率。

下次实际比赛最有价值的证据是150–260回合连续输入与输出，特别是基地等级、操作者HP/位置、背包、机器人位置/类型/目标阵营以及 `lastRoundRoleActionResults`。新版普通日志已补核心字段；完整请求可通过既有 `COMPETITION_TRACE` 记录。没有连续结算时，不把“发出use”当成“升级成功”，也不把“没有找到某条use”当成“绝对没用过”。

## 外部事实证据

- 检查时间：2026-09-18，Asia/Shanghai。
- 触发原因：实战复盘涉及昼夜阶段、炮台射程、升级与角色复活，需按官方规则纠正模型。
- 本地版本：待发布Python标准库Bot，入口 `CoreGeek/main3.py`，最低Python3.11；已发布对照版本 `b471f44`。
- 查询入口：[官方任务书](https://github.com/Tymonxiong/Competition/blob/7e629424c87f3f194d071696d3ee59a8dc2c0a75/docs/任务书.md)、[官方接口](https://github.com/Tymonxiong/Competition/blob/7e629424c87f3f194d071696d3ee59a8dc2c0a75/docs/接口文档.md)，v1.0、2026-09-09；线上内容与本地副本核对。
- 采用结论：70/60阶段、3格机器人射程、每角色每回合一个动作、2×2基地、升级回满血与次日复活。机器人的具体选择逻辑和墙挡弹机制没有据此被证明。
- 残留风险：没有正式判题器或本次原始状态；本地回归与模拟通过不能替代用户平台复测，也不能承诺100%正式胜率。
