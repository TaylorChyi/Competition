# Competition Bot · 直接上传最新包

在 [最新 Release](https://github.com/TaylorChyi/Competition/releases/latest) 的 Assets 中下载 **`CoreGeek-v日期-提交号.tar.gz`**，直接交给比赛平台，无需编译、安装依赖或重新打包。每次发布的文件名都带版本号，例如 `CoreGeek-v2026.09.18-ffc174b.tar.gz`；只保留最新比赛包 Release，源码仓库不存放压缩包。外部文件名变化不影响包内固定的 `CoreGeek/main3.py` 入口。

## 平台解压与启动

压缩包采用官方 Demo 的单一顶层目录 `CoreGeek/`。解压到 `/home/docker` 后，启动入口应为：

```text
/home/docker/CoreGeek/main3.py
```

当平台已将文件放在该位置时，使用：

```bash
python3 /home/docker/CoreGeek/main3.py 6666
```

`6666` 来自本次正常运行日志，仍以平台指定端口为准。也支持 `bash /home/docker/CoreGeek/run.sh 6666`。程序监听 `0.0.0.0:<port>`，通过 HTTP 接收游戏状态并返回动作；保持前台运行。

用户已确认采用此结构的包可在内网平台运行。本版保持相同目录和启动入口。遇到新的入口问题时，可用当前 Release 的“预检启动命令”打印路径并定位本版程序；详见[平台启动排查](https://github.com/TaylorChyi/Competition/blob/main/docs/平台启动排查.md)。

接收者不需要搭建编译环境。程序使用比赛平台已有的 Python，最低要求为 3.11；包内不包含 Python 解释器，不需要第三方 Python 库、GPU、模型下载或 API Key。用户提供的正常日志显示解释器为 `/usr/local/bin/python3.11`；具体补丁版本未知。

## 可选：连通性检查

程序启动日志第一行固定为 `Caffeine-Taylor`，随后显示 `CoreGeek startup | package=... python=... entry=... runtime=...` 和 `listening on 0.0.0.0:6666`。预检启动命令也会先输出同一标识，再打印路径检查结果。`package` 指纹用于区分上传的新旧包。

服务启动后，在日志中 `runtime=` 指向的目录运行：

```bash
curl -sS -H 'Content-Type: application/json' \
  --data-binary @sample-request.json http://127.0.0.1:6666/
```

应返回包含 `roleCommandMap` 的动作 JSON。比赛平台负责连续提供状态和结算动作。

## 本版防守改动

三种武器只选择 `robot.targetTeam` 与 `teamOur.type` 相同的机器人，即攻击我方阵营的机器人。机器人绕路时也按平台给定阵营判断；对方机器人的位置仍会用于避障。缺少有效阵营字段时不选择攻击目标，并在日志中暴露该情况。

先建三座基础电磁炮，再由一名工人逐步补足18块围墙，留两个出口供采矿和回防；另一名工人继续赚钱，开拓者采购送券。优先补齐缺口，再维护残墙；金币用于基地急救和炮台升级，没有新增常规围墙升级采购。墙用石料，炮升级用金币，主要权衡在工人的劳动时间。双出口已验证两侧所有空闲内侧站位均可通向外部，避免围墙把炮手封死。

按目标阵营分配火力，清理高威胁且能快速击杀的机器人；最多三炮联合比较六种射击顺序，只有有效伤害不降低、预测击杀更多且威胁收益更高时才调整，避免灵活炮抢走受限炮的唯一目标；不把整晚都耗在满血 BOSS 上。白天提前调整到炮台后排，夜间遇到高死亡风险才换位，避免频繁走动损失火力；濒死时允许暂时脱离炮台。

白天根据当前售价采集和卖矿，由开拓者采购升级券。可升级基地低于当前满血的75%时优先筹备基地升级；仅轻伤时允许先升级武器，提高后续防守火力。已经持有的基地券仍送达即用。正式任务书明确升级恢复满血。本版也会补建受损围墙、在缺少升级券时付费重建严重受损的炮台，并提前回防。所有采购都预留去商店和返回防线的时间；夜间不出门购物。基地券送达即用，危急时优先于吃药；下一回合的等级与动作结果用于核对是否生效。买药预留下一张基地券的实际费用，满包和现金不足时不发购买指令。交易入口发生碰撞后，改走另一个合法邻格，避免带着矿一直堵在商店外。

回合日志包含 `team`、`incoming`、`unknown_target`、上轮失败动作；新增 `battlefield` 显示基地等级/HP、角色位置/背包及各炮台未开火状态。`no-incoming-in-range` 表示没有我方来袭目标进入射程，`no-adjacent-operator` 表示缺炮手，`adjacent-operators-busy` 表示附近角色正在移动或用物品，`attack-issued` 仅表示已发攻击。

## 可选：范围攻击试验策略

仅当场上已有火箭炮时，此配置覆盖它的默认选点；普通上传使用默认策略即可：

```bash
COMPETITION_ROCKET_POLICY=selected-policy.json \
  python3 /home/docker/CoreGeek/main3.py 6666
```

历史范围参数不改变默认三电磁炮的建造配置，不能把启用它当作切换了整套阵容。停止服务、取消该环境变量并使用普通命令即可恢复默认。

## 包内内容

`CoreGeek/main3.py`、`CoreGeek/src/agent/` 和 `CoreGeek/run.sh` 是运行入口与算法；所有文件均在同一个 `CoreGeek/` 目录内。`selected-policy.json` 是可选策略配置；`sample-request.json` 是请求样例；`MANIFEST.json` 记录运行目录各文件的 SHA-256。`pyproject.toml` 仅说明 Python 版本，直接启动不需要安装项目。

本版来自三位Agent对实战反馈的修复与循环比赛。每对10组换边赛、并列加赛5组，冠军发布新包，败者继承冠军继续改进。[锦标赛进度](https://github.com/TaylorChyi/Competition/blob/main/docs/锦标赛进度.md)记录胜率、连续多夜生存和失败；[实战修复说明](https://github.com/TaylorChyi/Competition/blob/main/docs/第二晚实战修复.md)区分已修缺陷与仍未知机制。用户已确认上一版的目录和启动方式可用；本版的正式平台生存成绩仍需实测。模拟不含任务、新闻、宝藏收入，也没有官方完整判题器。

本版沿用两座前炮、一座侧后炮，位置由收到的基地坐标计算。在用户确认“机器人每回合移动或攻击二选一，攻击最近或挡路单位”后，18墙双出口通过开发8/8和独立验证20/20，全部活到第1300回合、零非法指令。各轮模拟成绩和未采用的尝试见仓库 `docs/锦标赛进度.md`，围墙与火力对照见 `docs/十晚生存门槛.md`；以上100%仅覆盖该本地测试集，不代表正式比赛必胜。
